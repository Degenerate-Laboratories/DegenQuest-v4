# Cursor Rules for DegenQuest-v4

## Overview
This document outlines the rules and guidelines for using Cursor with the DegenQuest-v4 project. These rules ensure consistent development practices and adherence to the guild protocol.

## Guild Protocol
All development work must follow the established guild protocol, which is documented in the following locations:

- **Milestone & Sprint Process**: [docs/guild/milestone-sprint-process.md](./guild/milestone-sprint-process.md)
- **Branching Strategy**: [docs/guild/branching.md](./guild/branching.md)
- **Templates**:
  - Sprint Plan: [docs/guild/sprint-plan-template.md](./guild/sprint-plan-template.md)
  - Sprint Report: [docs/guild/sprint-report-template.md](./guild/sprint-report-template.md)
  - Milestone: [docs/guild/milestone-template.md](./guild/milestone-template.md)

## Key Rules

### Sprint Approval Process
1. **Sprint Creation**: All work must be part of a numbered sprint (e.g., Sprint 1, Sprint 2)
2. **Documentation**: A sprint plan document must be created using the template
3. **Approval**: The sprint must be approved before work begins
4. **Milestone Assignment**: Each sprint must be associated with a milestone

### Branching
1. Follow the branching strategy in [docs/guild/branching.md](./guild/branching.md)
2. Branch naming convention:
   - Feature branches: `feature/feature-name`
   - Bug fixes: `bugfix/issue-description`
   - Hotfixes: `hotfix/issue-description`
   - Releases: `release/version-number`

### Code Standards
1. **TypeScript**: All code must use TypeScript with proper type definitions
2. **Comments**: Code should include meaningful comments
3. **Style**: Follow existing code style and conventions in the codebase
4. **Testing**: Changes should be tested thoroughly before submission

### Documentation
1. All features must be documented
2. Update existing documentation to reflect changes
3. Use inline comments for complex implementations
